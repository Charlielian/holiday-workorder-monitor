# NetSentinel — 无线网络性能超频小区小时级监控与治理平台

**NetSentinel** 是专为移动通信无线网优运维打造的性能劣化与超频小区全自动监控系统。系统内置 10 类 4G/5G 核心性能劣化规则判定引擎，通过 8 小时滑动时间窗口算法实时捕获网元复现频次，精准锁定 3 天以上高频恶化（超频）小区，为网优人员提供小时级监控看板、天级超频汇总以及严格对齐“上周五至本周四”网优考核周期的专项治理报表。

系统采用模块化单体架构设计，原生支持离线环境独立部署，具备高吞吐数据流、断点续采、图形验证码快速续期以及双数据库无缝切换能力。

---

## 核心特性

- **10 大类性能问题规则精准判定**：
  - **4G 规则**：VoLTE高掉线小区、LTE掉线高小区、LTE接通低小区、VoLTE无线接通低小区、4G下行低速率小区。
  - **5G 规则**：VoNR业务Flow掉线高小区、SA高掉线小区、SA低接通小区、VoNR无线接通率低、5G下行低速率小区。
- **8 小时滑动窗口复现算法**：
  - 针对每个小区在滑动时间窗口 $[T - 7\text{h}, T]$ 内同问题类型的出现次数进行统计。
  - 首次发生记为 `复现 (0次)`，再次发生精准计算为 `复现 (N-1次)`，不同问题类型彼此独立隔离统计。
- **达标超频判定机制（复现 $\ge 3$ 天）**：
  - 本日超频看板以网元/小区为主体聚合展示为单行，多类型问题使用独立标签并列呈现。
  - 自动回溯小区历史上出现滑动复现问题的天数，严格将 $\ge 3$ 天的小区锁定为红色高亮“超频”网元。
- **网优周考核周期自动对齐**：
  - 严格按照通信行业“**上周五 00:00 至 本周四 23:59**”动态切片，自动筛选周期重点整治网元（恶化 $\ge 2$ 天 或 累计时段 $\ge 5$ 次），支持一键导出标准 Excel。
- **完全自包含与离线部署**：
  - NQI 数据采集与认证模块完全内化，前端依赖（Vue 3、Element Plus）本地化托管，无需 Node 构建与外网环境，开箱即用。
- **双数据库平滑切换**：
  - 原生支持 **MySQL**（生产高并发）与 **SQLite WAL**（轻量免运维），在配置文件中一键切换。
- **断点续采与会话维持保护**：
  - 会话失效时定时调度器安全挂起，Web 界面状态灯实时告警，支持弹出图形验证码一键续期，续期后自动触发断点续采补齐数据。

## 业务视图一览

1. **最新时段监控**：当前小时质差小区清单、8 小时复现次数标记、4G/5G 占比及实时指标卡。
2. **本日超频看板**：以网元为主体单行聚合展示，多问题标签化，清晰呈现复现天数与超频状态。
3. **周考核(五至四)**：对齐网优周期，展示重点整治网元并支持多 Sheet Excel 导出。
4. **任务日志与补采**：后台小时抽取与分析流水明细，支持任意时间段手动触发补采。

## 快速上手

### 1. 安装依赖

```bash
git clone https://github.com/Charlielian/NetSentinel.git
cd NetSentinel
pip install -r requirements.txt
```

### 2. 配置说明

复制配置样例：
```bash
cp config/config.example.yaml config/config.yaml
```
编辑 `config/config.yaml` 配置系统端口、数据库选型（`sqlite` 或 `mysql`）及相关凭据。

### 3. 启动服务

```bash
python3 main.py
```
启动成功后，在浏览器访问：`http://127.0.0.1:8000` 即可进入 NetSentinel 控制台。

## 目录架构

```text
NetSentinel/
├── config/                  # 配置文件目录 (规则定义、字段映射、基础配置)
├── core/                    # 核心引擎 (10类规则引擎、8h滑动超频算法、调度器、NQI采集)
│   ├── nqi/                 # 内化封装的 NQI 即席查询采集客户端
│   ├── overclock_engine.py  # 8小时滑动窗口与日/周超频计算核心
│   ├── rule_evaluator.py    # 10类质差规则评估器
│   └── scheduler.py         # APScheduler 定时小时调度与断点续采
├── db/                      # 数据持久层 (SQLAlchemy 模型定义与双数据库管理器)
├── services/                # 业务服务层 (监控聚合、Excel导出、会话认证、ETL管道)
├── web/                     # Web 控制台与静态资源 (Vue 3 + Element Plus 单体应用)
│   └── static/              # 本地化离线前端库 (JS / CSS / 图标)
├── main.py                  # 服务统一启动入口
└── requirements.txt         # Python 依赖清单
```
